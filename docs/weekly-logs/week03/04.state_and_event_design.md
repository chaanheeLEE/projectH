# 📊 주문 상태 전이 및 도메인 이벤트 흐름 설계서

## 1. 🔄 주문 상태 전이 다이어그램 (Order Status State Machine)
주문의 상태는 아래와 같이 전이되며, 한 번 최종 상태(`CANCELLED`, `FAILED`)에 도달한 주문은 상태 변경이 차단됩니다.

```mermaid
stateDiagram-v2
    [*] --> PENDING : 주문 API 요청 (Order.create)
    
    PENDING --> STOCK_DEDUCTED : 재고 차감 성공 (completeStockDeduction)
    PENDING --> FAILED : 재고 차감 실패 / 락 재시도 초과 (fail)
    
    STOCK_DEDUCTED --> PAYMENT_APPROVED : 결제 요청 성공 (approvePayment)
    STOCK_DEDUCTED --> CANCELLED : 결제 요청 실패 (보상 트랜잭션 - cancel)
    
    PAYMENT_APPROVED --> [*]
    CANCELLED --> [*]
    FAILED --> [*]
```

---

## 2. ⚡ 도메인 이벤트 흐름도 (Event & Compensating Transaction Flow)
각 트랜잭션이 독립된 비동기 스레드에서 Saga 형태로 실행되는 흐름과 예외 발생 시의 보상 트랜잭션 흐름입니다.

### 1) 정상 흐름 (Happy Path)
```mermaid
sequenceDiagram
    autonumber
    actor User as 구매자
    participant API as OrderController
    participant SVC as OrderService
    participant DB as Database (Orders)
    participant LSN as OrderEventListener
    participant FAC as StockDeductionFacade
    participant PROD as ProductService
    participant PAY as PaymentService

    User->>API: 주문 요청 (POST /api/orders)
    API->>SVC: createOrder()
    SVC->>DB: 주문 저장 (PENDING)
    SVC-->>API: 주문 임시 생성 완료 응답 (PENDING)
    API-->>User: 주문 응답 반환
    
    Note over SVC: [Transaction 1 Commit]
    SVC-xLSN: OrderPlacedEvent 발행 (비동기)
    
    LSN->>FAC: deductStock()
    Note over FAC: [Transaction 2 Start - REQUIRES_NEW]
    FAC->>PROD: decreaseStock() (재고 차감)
    FAC->>SVC: completeStockDeduction() (주문 상태 -> STOCK_DEDUCTED)
    Note over FAC: [Transaction 2 Commit]
    FAC-xLSN: StockDeductedEvent 발행 (비동기)
    
    LSN->>PAY: requestPayment() (가상 결제 요청)
    LSN->>SVC: approvePayment() (주문 상태 -> PAYMENT_APPROVED)
    Note over SVC: [Transaction 3 Commit]
```

### 2) 결제 실패 시 보상 트랜잭션 흐름 (Compensation Path)
```mermaid
sequenceDiagram
    autonumber
    actor User as 구매자
    participant API as OrderController
    participant SVC as OrderService
    participant DB as Database (Orders)
    participant LSN as OrderEventListener
    participant FAC as StockDeductionFacade
    participant PROD as ProductService
    participant PAY as PaymentService

    User->>API: 주문 요청 (POST /api/orders)
    API->>SVC: createOrder()
    SVC->>DB: 주문 저장 (PENDING)
    SVC-->>API: 주문 임시 생성 완료 응답
    
    Note over SVC: [Transaction 1 Commit]
    SVC-xLSN: OrderPlacedEvent 발행 (비동기)
    
    LSN->>FAC: deductStock()
    Note over FAC: [Transaction 2 Start]
    FAC->>PROD: decreaseStock() (재고 차감)
    FAC->>SVC: completeStockDeduction()
    Note over FAC: [Transaction 2 Commit]
    FAC-xLSN: StockDeductedEvent 발행 (비동기)
    
    LSN->>PAY: requestPayment() (한도초과 등 실패 발생!)
    PAY-->>LSN: 예외 발생 (IllegalArgumentException)
    
    Note over LSN: [보상 트랜잭션 (Compensating Tx) 실행]
    LSN->>PROD: increaseStock() (차감된 재고 복구)
    LSN->>SVC: cancelOrder() (주문 취소 -> CANCELLED)
```
