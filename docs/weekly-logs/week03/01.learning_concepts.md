# 📚 [3주차] 필수 이론 학습 및 개념 정리 노트

## 1. 🧩 핵심 개념 이론 정리

### 1) DDD(도메인 주도 설계)와 주문 애그리거트(Order Aggregate)
*   **Entity vs Value Object (VO)**
    *   **Entity (엔티티)**: 고유한 식별자(ID)를 가지며, 필드 값들이 변하더라도 식별자가 같다면 동일한 객체로 취급됩니다. 주문(`Order`), 상품(`Product`)이 이에 해당합니다.
    *   **Value Object (VO, 값 객체)**: 고유 식별자가 없고 오직 속성들의 조합으로만 식별성을 가집니다. VO는 항상 **불변성(Immutability)**을 지켜야 하므로 수정 시 새로운 VO 객체를 반환해야 합니다. 주문항목(`OrderItem`), 금액(`Money`), 재고(`Stock`)가 이에 해당합니다.
*   **Aggregate (애그리거트)와 Aggregate Root**
    *   애그리거트는 데이터 변경 시 단위가 되는 도메인 객체들의 논리적인 묶음입니다.
    *   **Aggregate Root (애그리거트 루트)**: 애그리거트를 제어하고 외부와 소통하는 단일 진입점입니다. 애그리거트 내부 객체(예: `OrderItem`)는 직접 영속화되거나 외부에서 수정되지 못하고, 항상 루트(`Order`)를 통해서만 라이프사이클이 관리되어야 데이터의 일관성(Invariants)이 유지됩니다.

### 2) Spring ApplicationEvent 기반 이벤트 주도 아키텍처
*   **이벤트 주도 설계 (Event-Driven Design)**
    *   하나의 작업이 완료되면 이벤트를 발행하고, 이벤트를 구독하는 리스너가 후속 작업을 처리하여 도메인 및 서비스 간 결합도(Coupling)를 낮춥니다.
*   **@TransactionalEventListener**
    *   이벤트를 발행한 본래 트랜잭션의 커밋 여부에 연동하여 리스너의 실행 시점을 조절할 수 있습니다.
    *   `TransactionPhase.AFTER_COMMIT`을 사용하면 주문 트랜잭션이 최종 DB 커밋 완료된 성공 시점에만 비동기로 재고 차감 및 결제 요청 작업을 수행하게 제어할 수 있습니다.
*   **@Async 비동기 처리**
    *   호출한 스레드와 다른 백그라운드 스레드 풀에서 작업을 비동기로 실행합니다. 사용자 요청 스레드는 오랜 시간이 걸리는 결제 API 대기를 기다리지 않고 즉시 주문 성공(PENDING) 응답을 받음으로써 시스템 반응 속도를 대폭 높입니다.

### 3) 낙관적 락(Optimistic Lock)을 이용한 동시성 제어
*   **낙관적 락 (Optimistic Lock)**
    *   대부분의 트랜잭션이 충돌하지 않는다고 가정하고, 데이터베이스 단에서 실제로 락을 거는 대신 데이터 조회 시점의 버전(`@Version`)을 저장 시점의 버전과 비교하여 충돌을 감지하는 방식입니다.
    *   충돌이 발생하면 `OptimisticLockingFailureException` 예외가 던져지며 이를 애플리케이션 레이어에서 캐치하고 적절한 예외 복구(재시도) 처리를 거칩니다.
*   **Spring Retry (@Retryable)**
    *   낙관적 락 실패 시 일어나는 예외에 대해 선언적으로 재시도를 수행하게 해주는 라이브러리입니다.
    *   최대 재시도 횟수, 재시도 간격(Backoff) 등을 설정하여 일시적인 동시성 충돌을 유연하게 완화시킵니다.

## 2. 📂 아키텍처 및 아키텍처 규칙 설계
*   **계층 간 의존성 방향 제한**
    *   육각형(헥사고날) 아키텍처 원칙에 따라, 안쪽의 순수 도메인 모듈(`projecth-domain`)은 바깥쪽 모듈(`projecth-application`, `projecth-infrastructure`, `projecth-api`)의 클래스나 프레임워크(Spring, JPA 등)에 절대 의존하지 않는 순수 Java 코드로 격리하였습니다.
    *   비즈니스 유스케이스(`projecth-application`)는 도메인 모듈을 호출하고, 인프라나 DB 제어는 포트(`Port`) 인터페이스를 통해서만 상호작용하여 의존성 역전 원칙(DIP)을 엄격히 적용하였습니다.
