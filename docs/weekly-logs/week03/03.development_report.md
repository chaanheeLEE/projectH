# 📝 [3주차] 개발 결과 보고서

## 1. 🛠️ 이번 주차 개발 요약
- **주문 도메인 구현 및 영속성 매핑**:
  - `Order` Aggregate Root와 `OrderItem` VO, `OrderStatus` Enum을 도메인 모듈에 구현하였습니다.
  - JPA에 의존하지 않는 순수 도메인 설계를 준수하였으며, 영속성 모듈(`projecth-infrastructure`)에 JPA Entity 및 Mapper를 구축해 DB 구조와 도메인 구조를 완전히 분리하였습니다.
- **Spring ApplicationEvent 기반 비동기 트랜잭션 분리**:
  - `@Async`와 `@TransactionalEventListener(phase = TransactionPhase.AFTER_COMMIT)`를 활용하여, 주문 생성 완료 시 트랜잭션을 빠르게 Commit하고 후속 작업(재고 차감, 결제 요청)은 백그라운드 스레드에서 격리되어 실행되도록 구축했습니다.
- **결제 실패 보상 트랜잭션 설계**:
  - 비동기 결제 요청 실패 시, 이미 성공했던 재고 차감을 원복하기 위해 상품 재고를 복구(`increaseStock`)하고 주문의 최종 상태를 `CANCELLED`로 변경하는 보상 트랜잭션(Compensating Transaction)을 정상적으로 구현하였습니다.
- **낙관적 락을 이용한 재고 동시성 제어 및 재시도 기법**:
  - `Product` 도메인 및 JPA Entity에 `@Version` 정보를 추가해 동시 변경 충돌을 감지하게 설계했습니다.
  - 낙관적 락 충돌(`OptimisticLockingFailureException`)이 발생하면 스프링 리트라이(`@Retryable`)를 타고 최대 5회 백오프 재시도를 하도록 구축했습니다.
- **API DTO 유효성 검증(Bean Validation)**:
  - 주문 생성 DTO(`CreateOrderRequest`, `OrderItemRequest`)에 필드 유효성 검증 규칙을 추가했습니다.
  - 기존 상품(`RegisterProductRequest`, `StockRequest`, `UpdateStatusRequest`) 및 장바구니(`AddCartItemRequest`, `UpdateCartItemRequest`) DTO에도 유효성 어노테이션을 보완 적용하고 컨트롤러 진입부에 `@Valid`를 적용했습니다.

## 3. ⚙️ 핵심 비즈니스 로직 및 구현 상세
- **주문 생명주기 관리**:
  - 주문 접수 시 `PENDING` 상태로 임시 생성되며, 사용자 스레드는 즉시 주문 ID를 반환받습니다.
  - 비동기 스레드에서 재고 차감 및 결제가 순차적으로 진행됩니다.
  - 최종 성공 시 `PAYMENT_APPROVED`, 재고 부족 실패 시 `FAILED`, 결제 승인 실패 시 `CANCELLED` 상태로 전이합니다.
- **보상 트랜잭션**:
  - 결제 모듈에서 한도 초과 등의 이유로 에러가 리턴되면, `OrderEventListener`가 이를 트래치하여 각 주문 항목별 차감했던 재고를 데이터베이스에 다시 원복(`increaseStock`)하고 주문 엔티티를 `CANCELLED`로 변경합니다.

## 4. 🌐 REST API 명세

### 1) 주문 생성 API
*   **Endpoint**: `POST /api/orders`
*   **Request Header**: `Content-Type: application/json`
*   **Request Body**:
    ```json
    {
      "buyerId": 1,
      "items": [
        {
          "productId": 1,
          "price": 100000.00,
          "quantity": 2
        }
      ]
    }
    ```
*   **Response Body (HTTP 200 OK - PENDING 상태 반환)**:
    ```json
    {
      "id": 1,
      "buyerId": 1,
      "orderItems": [
        {
          "productId": 1,
          "price": 100000.00,
          "quantity": 2
        }
      ],
      "totalPrice": 200000.00,
      "status": "PENDING"
    }
    ```

### 2) 주문 단건 조회 API
*   **Endpoint**: `GET /api/orders/{id}`
*   **Response Body (HTTP 200 OK)**:
    ```json
    {
      "id": 1,
      "buyerId": 1,
      "orderItems": [
        {
          "productId": 1,
          "price": 100000.00,
          "quantity": 2
        }
      ],
      "totalPrice": 200000.00,
      "status": "PAYMENT_APPROVED"
    }
    ```
