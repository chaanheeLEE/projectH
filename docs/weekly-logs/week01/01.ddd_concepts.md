# 📖 에릭 에반스 DDD 핵심 개념 정리

1주차 DDD 도메인 모델링을 위한 설계 기반이 되는 핵심 구성 요소들(Entity, VO, Aggregate, Repository, Domain Service)에 대해 커머스 도메인을 예시로 들어 정리합니다.

---

## 1. 엔티티 (Entity)
엔티티는 **고유한 식별자(Identifier)**를 가지며, 그 식별자를 통해 상태가 변하더라도 지속해서 동일한 객체로 인식되는 도메인 개념입니다.

*   **특징**:
    *   생명주기를 가지며 생성, 수정, 삭제(소멸) 과정을 거칩니다.
    *   속성(Attribute) 값이 일치하더라도 식별자가 다르면 다른 엔티티로 간주합니다.
*   **커머스 예시 — `Product` (상품)**:
    *   상품의 가격이나 재고, 이름이 변경되더라도 `productId`라는 고유 식별자가 유지되므로 동일한 상품으로 인식됩니다.
*   **커머스 예시 — `Order` (주문)**:
    *   주문 상태가 `주문 접수`에서 `결제 완료`로 변경되더라도 `orderId`를 통해 동일한 주문임을 식별합니다.

---

## 2. 값 객체 (Value Object, VO)
값 객체는 고유 식별자가 없으며, **담고 있는 속성 값 자체**가 식별 기준이 되는 객체입니다.

*   **특징**:
    *   **불변성(Immutability)**: 값이 생성된 후 변경되지 않아야 하며, 값을 수정해야 하는 경우 새로운 VO 객체를 생성하여 교체합니다.
    *   **자가 검증(Self-Validation)**: 객체 생성 시점에 유효성 검증을 수행하여 비정상적인 상태의 객체 생성을 원천 차단합니다.
*   **커머스 예시 — `Money` (금액)**:
    *   `private final BigDecimal amount` 속성을 가지며, 덧셈/뺄셈 연산 시 새로운 `Money` 객체를 반환합니다.
*   **커머스 예시 — `Address` (배송지 주소)**:
    *   우편번호, 시/도, 구/군, 상세 주소의 값들이 결합하여 하나의 주소 정보를 나타냅니다. 주소가 바뀌면 필드 하나만 바꾸는 것이 아니라 주소 객체 자체를 새로 만들어 할당합니다.

---

## 3. 애그리거트 (Aggregate)
애그리거트는 **관련 엔티티와 값 객체(VO)를 하나의 트랜잭션 경계로 묶은 도메인 객체들의 집합**입니다.

*   **특징**:
    *   **애그리거트 루트(Aggregate Root)**: 애그리거트 외부에서는 오직 루트 엔티티를 통해서만 애그리거트 내부 멤버에 접근하고 수정할 수 있습니다.
    *   **도메인 규칙 일관성 보장**: 데이터의 변경은 애그리거트 루트 내 비즈니스 로직을 통해서만 수행되며, 이를 통해 애그리거트 전체의 일관성(Invariants)을 유지합니다.
*   **커머스 예시 — `Order` 애그리거트**:
    *   **루트**: `Order` (엔티티)
    *   **내부 구성원**: `OrderItem` (엔티티 - Order 외부에서 직접 수정할 수 없음), `ShippingAddress` (VO), `OrderStatus` (Enum/VO)
    *   **규칙**: 주문 수량을 변경하거나 품목을 추가하려면 `Order` 루트의 `changeItemQuantity()` 또는 `addItem()` 메서드를 거쳐야 하며, 이때 전체 주문 금액 등의 비즈니스 일관성이 검증됩니다.

---

## 4. 리포지토리 (Repository)
리포지토리는 **애그리거트 루트 객체의 영속성(Persistence)을 담당하는 메커니즘을 추상화한 인터페이스**입니다.

*   **특징**:
    *   영속성 계층(DB 등)과의 직접적인 통신을 도메인 레이어로부터 숨깁니다.
    *   도메인 레이어는 마치 메모리 컬렉션에서 객체를 꺼내고 넣는 것처럼 리포지토리를 사용합니다.
    *   애그리거트 내부 엔티티(예: `OrderItem`)를 위한 별도의 리포지토리는 원칙적으로 두지 않으며, 반드시 루트 리포지토리(예: `OrderRepository`)를 통해서만 저장 및 조회합니다.
*   **커머스 예시 — `OrderRepository`**:
    *   `Order save(Order order)`: 주문 애그리거트 전체를 영속화합니다.
    *   `Optional<Order> findById(OrderId id)`: 주문 식별자로 주문 애그리거트 전체를 조회합니다.

---

## 5. 도메인 서비스 (Domain Service)
도메인 서비스는 **특정 엔티티나 VO의 내부 상태 및 메서드로만 책임을 할당하기에 어색한 다중 애그리거트 비즈니스 로직**을 수행하는 상태가 없는(Stateless) 서비스입니다.

*   **특징**:
    *   상태를 가지지 않으며 단지 비즈니스 행위만을 제공합니다.
    *   엔티티 내부에 애플리케이션 인프라 의존성(예: 암호화 라이브러리, 외부 PG 연동)을 주입하기 힘들 때 도메인 서비스를 정의하여 역할을 위임합니다.
*   **커머스 예시 — `DiscountCalculator` (할인 적용 계산 서비스)**:
    *   회원 등급 애그리거트와 상품 애그리거트의 정보를 둘 다 참조하여 최종 할인 가격을 계산하는 경우.
*   **커머스 예시 — `PasswordEncryptor` (비밀번호 암호화 서비스)**:
    *   `Member` 엔티티 내에 특정 해시 알고리즘 빈을 주입받아 처리하기 모호하므로, 비밀번호 변경 도메인 서비스를 두어 처리합니다.
