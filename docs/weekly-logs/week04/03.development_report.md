# 📝 [4주차] 개발 결과 보고서

## 1. 🛠️ 이번 주차 개발 요약
- **포트원(PortOne) PG 연동 구조 설계**: 포트원 SDK 결제 흐름 분석 및 백엔드 승인/검증 파이프라인 구현
- **결제 상태 머신(Payment State Machine)**: `INITIATED` -> `PG_REQUESTED` -> `APPROVED` -> `COMPLETED` / `FAILED` / `CANCELLED` 간의 엄격한 상태 전이 및 캡슐화 구현
- **중복 결제 방지 (Idempotency)**: 클라이언트/주문 멱등키(`idempotencyKey`) 기반으로 동일 요청 수신 시 기존 결제 응답을 반환하는 멱등성 보장
- **서버 측 결제 위변조 검증 (Server-Side Verification)**: PG사 단건 결제 조회 API를 백엔드에서 수행하여 PG 실제 결제 금액과 서버 주문 금액 재검증 및 위변조 시 자동 PG 취소/실패 처리
- **전체 단위/통합 테스트 작성 및 검증**: 멱등성 검증, 결제 위변조 감지 및 자동 취소, 정상 결제 검증 통합 테스트 수행 완료

## 3. 🌐 REST API 명세

| 기능 | HTTP Method | Endpoint | 설명 |
| :--- | :--- | :--- | :--- |
| **결제 준비** | `POST` | `/api/v1/payments/prepare` | `INITIATED` 상태 결제 생성 및 멱등키 등록 |
| **결제 검증 및 승인** | `POST` | `/api/v1/payments/verify` | PG 단건 결제 조회 후 금액 검증 및 승인 (`APPROVED`/`COMPLETED`) |
| **결제 내역 조회** | `GET` | `/api/v1/payments/{idempotencyKey}` | 멱등키 기준 결제 결과 단건 조회 |
